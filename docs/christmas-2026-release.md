# 2026 크리스마스 예약 릴리스

기준: 2026-11-23, 한국 시간. 이전 개발 가이드의 과거 초안 상태 설명보다 이 문서의 운영 현황을 우선한다.

## 배포 현황

- GitHub Pages `master`: 행사 소개, 예약 신청·접수 화면, 2026 관리자 대시보드와 대기열 화면 배포. 대기열 PR #35 병합 커밋 `7029d7324ddb8e074e34306835dce183769f01c7`, 배포 실행 `45198049399` 성공.
- Supabase 기존 프로젝트: 2026 예약 및 별도 대기열 저장소, 관리자 승인 함수, 공개 예약·대기 신청 Edge Function 배포.
- 예약 스위치는 켜져 있으며 생성 함수는 한국 시간 2026-11-24 00:00 이전 접수를 거부한다. 오픈 이후 실제 전체 사용자 흐름은 확인 전이다.
- 종전 예약 및 대기 데이터는 삭제하지 않았으며, 관리자 화면에서 2025년 목록과 집계를 숨겼다.

## 운영 조건

- 행사일 2026-12-24, 2026-12-25; 회차 시작 11:30, 13:30, 17:30, 19:30; 식사 100분; 2~4인.
- 회차별 테이블은 2인용 2개, 3인용 1개, 4인용 2개. 서버가 수용 가능한 테이블을 배정한다.
- 코스 1인 120,000원, 선택 와인 페어링 1인 40,000원. 예약금 1인 30,000원은 신청 후 2시간 내 계좌이체, 잔액은 현장 결제.
- 신청은 즉시 확정이 아니다. 관리자가 입금을 확인하고 승인한다. 미입금 자동 취소는 없으며 직접 취소한다.
- 3일 전까지 전액 환불 안내를 사용한다. 세부 기준은 추가 확인이 필요하며 환불은 별도 처리한다.

## 관리자와 대기열

- `/admin`의 2026 예약 목록에서 입금 확인 후 승인하거나 수동 취소한다. 2026 데이터 접근에는 Supabase 관리자 인증이 필요하며, 기존 인증 세션이 없는 경우 별도 인증이 표시된다.
- 마감 회차 대기 신청은 별도 2026 저장소에 저장하고 순번을 서버에서 할당한다. 관리자는 대기 목록을 확인하고 직접 연락 완료 또는 취소를 표시한다.
- 대기자에게 자동 문자 발송이나 자동 예약 전환은 하지 않는다. 기존 2025 대기 데이터와 혼합하지 않는다.

## 확인 및 미확인

- 빌드와 로컬 정책·통계 테스트가 통과했다. 2026 대기열 테이블의 RLS 및 익명 직접 조회·생성 거부를 확인했다.
- 관리자 승인 및 감사 기록을 가상 예약으로 확인하고 트랜잭션을 롤백했다. 운영 관리자 화면에서 2026 예약·대기열 빈 목록 표시를 확인했다.
- 실제 고객 신청 → 저장 → 은행 입금 → 관리자 승인 전체 흐름과 마감 회차 대기 신청의 실제 브라우저 전체 흐름은 확인하지 않았다. 오픈 후 확인해야 한다.
- 같은 연락처의 같은 회차 중복 신청은 차단하지만 다른 연락처를 사용한 반복 신청은 막지 않는다. 운영자가 위험을 수용했다.
- 기존 대기열과 일부 과거 API의 권한 문제는 별도 보안 대응 항목이다. 화면에서 숨긴 것은 기존 API의 접근 권한을 수정한 것이 아니다.
- 미커밋된 로컬 테스트·개발 문서·시안은 운영 배포에 포함되지 않는다. 비밀번호·키·고객 정보는 이 문서와 Git에 기록하지 않는다.
